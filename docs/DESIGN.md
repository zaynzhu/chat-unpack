# ChatUnpack v0.1 详细设计

> 状态：macOS v0.1 已实现并通过静态构建、核心测试与离线隐私审计；真实窗口验收待用户使用无隐私样本确认
>
> 首要平台：macOS 13 及以上，Apple Silicon
>
> 后续平台：Windows 11 23H2 及以上，x64
>
> 使用范围：个人自用
>
> 文档日期：2026-08-21

## 1. 文档目的

本文档定义 ChatUnpack v0.1 的产品范围、隐私边界、交互流程、macOS 技术架构、窗口采集与 OCR 流程、数据模型、错误处理、测试策略和验收标准。

本文档同时是第一版实现的约束来源。实现若与本文档冲突，应先修改设计并解释原因，不能静默扩大权限、保存聊天数据或引入联网能力。

## 2. 产品定义

ChatUnpack 是一个完全离线的桌面工具。用户在官方微信桌面端中主动打开一份“合并转发聊天记录”详情窗口，再主动触发 ChatUnpack。ChatUnpack 自动从顶部滚动到末尾，通过系统窗口捕获和本地 OCR 忠实转写可见内容，最终生成可编辑、可复制、可保存的 Markdown。

ChatUnpack 不是微信聊天数据库导出器，也不是微信机器人。它不登录账号、不读取微信数据库、不调用微信内部协议、不注入微信进程，也不替用户发送任何内容。

### 2.1 最小闭环

```text
用户打开合并转发记录
        ↓
用户按全局快捷键或点击“开始汇总”
        ↓
确认当前目标窗口
        ↓
ChatUnpack 自动滚到顶部并逐屏采集
        ↓
系统本地 OCR + 顺序拼接 + 重复消除
        ↓
用户预览并修正低置信度文字
        ↓
用户复制 Markdown 或主动保存 .md
        ↓
用户自行发送给 Hermes
```

### 2.2 v0.1 成功标准

第一版在合成测试窗口中必须完成以下闭环：

1. 只在用户主动触发后开始工作。
2. 识别并确认当前最前面的目标记录窗口。
3. 自动滚到记录顶部，再自动滚动到末尾。
4. 使用 macOS 本地 Vision OCR 获取文字。
5. 按原始顺序保留昵称、时间和消息正文。
6. 不因跨屏重叠而丢消息、重复消息或改变顺序。
7. 低置信度识别结果必须可见，不得静默伪装成准确原文。
8. 结果可以编辑、复制或保存为 Markdown。
9. 扫描结束后不保留截图，不自动保存聊天内容。
10. 不产生任何网络请求。

### 2.3 明确不做

v0.1 不包含以下功能：

- 不读取或解密微信数据库。
- 不 Hook、注入、调试或修改微信进程。
- 不读取微信进程内存。
- 不调用未公开的微信接口或协议。
- 不自动登录微信。
- 不自动发送消息或文件。
- 不后台监听普通聊天或合并记录。
- 不扫描聊天列表、联系人列表或其他微信窗口。
- 不递归打开合并记录中的嵌套聊天记录卡片。
- 不上传 OCR 图片、聊天文本、日志或遥测数据。
- 不调用云端 OCR、LLM 或摘要服务。
- 不生成 AI 摘要，不改写聊天内容。
- 不自动纠正人名、号码、日期或语义。
- 不保留历史记录。
- 不做账号系统、云同步、团队协作或公开分发。
- 不做 Intel Mac 兼容。
- 不在 v0.1 中实现 Windows 客户端。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 合并记录 | 用户在单聊或群聊中通过“多选 + 合并转发”生成的聊天记录包 |
| 记录详情窗口 | 用户点击合并记录后打开的独立内容窗口，与记录最初来自单聊还是群聊无关 |
| 目标窗口 | 用户触发扫描时，当前最前面且经过确认的记录详情窗口 |
| 视口 | 目标窗口当前可见的消息区域 |
| 采集帧 | 目标窗口某一滚动位置的一次内存截图 |
| OCR 观察 | Vision 返回的一行文字、位置矩形、候选结果和置信度 |
| 消息块 | 一条消息的昵称、时间、正文、类型占位符及识别状态 |
| 扫描会话 | 从确认目标窗口到完成、取消或失败的一次完整运行 |
| 拼接 | 把相邻视口解析出的消息块合并为一条有序记录 |
| 低置信度 | OCR 置信度低于阈值，或跨屏匹配无法可靠确定的内容 |

## 4. 支持范围

### 4.1 平台

macOS v0.1：

- macOS 13 及以上。
- 仅 Apple Silicon，也就是 `arm64`。
- 仅支持官方稳定版微信。
- 不支持测试版、修改版、多开版或兼容层中的微信。
- 明暗主题都应支持。
- 窗口可位于任意显示器，但必须完整落在同一块显示器内。

Windows 后续版本：

- Windows 11 23H2 及以上。
- 仅 x64。
- 采用独立的 C# / .NET 8 + WPF 原生实现。
- 不与 macOS 共用 Electron、Flutter 或其他跨平台 UI 壳。

### 4.2 内容类型

v0.1 必须忠实转写：

- 发送者昵称。
- 可见时间文本。
- 文字消息。
- 文字中的原始换行。
- OCR 能识别的 Emoji 或特殊符号。
- 可见链接文字和 URL。

v0.1 对非文字内容采用占位符：

- 能可靠判断为图片时写 `[图片]`。
- 能可靠判断为语音时写 `[语音]`。
- 能可靠判断为视频时写 `[视频]`。
- 能可靠判断为文件时写 `[文件]`，若文件名可见则追加文件名。
- 能可靠判断为小程序或链接卡片时写对应占位符，并保留可见标题。
- 遇到嵌套聊天记录时写 `[聊天记录]`，不自动打开。
- 无法可靠分类但确认存在非文字内容时写 `[非文字消息]`，不得猜测具体类型。

### 4.3 容量目标

- 已验证范围：单份合并记录不超过 200 条消息。
- 超过 200 条时允许继续，但界面必须提示“超出已验证范围”。
- 不对文字总长度设置人为截断。
- 最大采集视口数：250。
- 单次扫描最长时间：15 分钟。
- 达到限制时停止，并把结果标记为“提取未完成”。

## 5. 隐私与安全边界

隐私边界是产品能力的一部分，不是可选优化。

### 5.1 硬性不变量

任何实现都必须满足：

1. 用户未主动触发时，程序不得捕获、OCR、枚举或监控微信窗口。
2. 每次扫描只能绑定用户确认的一个目标窗口。
3. 不得读取微信数据库、缓存目录、日志目录或进程内存。
4. 不得注入、Hook、修改或调试微信进程。
5. 不得调用微信内部接口、私有协议或账号接口。
6. 不得点击发送按钮、输入消息或向微信写入任何内容。
7. 不得把截图或聊天文字发送到网络。
8. 不得把截图写入磁盘、临时目录、崩溃附件或日志。
9. 不得把昵称、正文、缩略图或 OCR 原文写入诊断日志。
10. 不得后台持续监听剪贴板、屏幕或微信窗口。
11. 结果默认只存在于进程内存中。
12. 只有用户点击“保存 Markdown”时才能写出结果文件。
13. 只有用户点击“复制”时才能写入系统剪贴板。
14. 关闭结果后必须释放当前聊天文本和图像缓存。

### 5.2 明确触发

允许触发扫描的入口只有：

- 用户按下已配置的全局快捷键。
- 用户点击主窗口中的“开始汇总”。
- 用户从菜单栏图标中点击“开始汇总”。

程序启动、登录、开机自启、恢复前台或发现微信窗口时，都不得自动开始扫描。

### 5.3 权限

macOS 只允许申请：

- 辅助功能权限：确认前台窗口、监听是否切换窗口、执行滚动、检测扫描期间的人工输入。
- 屏幕与系统录音权限：通过 ScreenCaptureKit 捕获用户确认的目标窗口。

macOS 不允许申请：

- 完全磁盘访问权限。
- 通讯录、相册、相机、麦克风、位置等无关权限。
- 管理员权限。

权限请求规则：

- 首次启动不立即弹权限请求。
- 用户第一次点击“开始汇总”时，先解释用途，再由用户决定是否进入系统设置授权。
- 缺少权限时停止流程，不得尝试绕过系统安全机制。
- 权限被撤销后，下次扫描重新检查并给出明确提示。

### 5.4 网络

v0.1 不需要网络能力：

- 不声明网络权限。
- 不包含 HTTP 客户端依赖。
- 不做版本检查、自动更新、遥测、崩溃上传或在线帮助。
- 所有帮助内容随应用本地提供。

### 5.5 日志

允许记录：

- ChatUnpack 版本。
- macOS 版本和 CPU 架构。
- 权限是否具备。
- 是否找到目标窗口。
- 扫描状态迁移。
- 采集视口数量。
- 总耗时。
- OCR 行数和低置信度数量。
- 错误代码。
- 内存和性能统计。

禁止记录：

- 微信窗口截图。
- 窗口缩略图。
- 窗口标题原文。
- 微信联系人、群名和昵称。
- 消息正文。
- OCR 候选文字。
- 导出文件路径中的用户自定义文件名。
- 剪贴板内容。

窗口标题如需诊断，只记录不可逆的会话内短哈希；应用退出后不保存哈希映射。

### 5.6 真实微信验收边界

- 自动测试不得查看、截图、滚动、点击或读取用户真实微信。
- 开发阶段使用合成数据和专用模拟窗口。
- 真实微信验收必须由用户先准备无隐私的合并记录。
- 在用户再次明确授权前，开发工具和自动化流程不得操作真实微信窗口。
- 用户提供的真实截图不得加入仓库或测试资源。

### 6.1 模块职责

#### ChatUnpackApp

- 应用生命周期。
- 主窗口与菜单栏入口。
- 全局快捷键注册。
- 设置加载与保存。
- 扫描状态展示。
- 结果编辑器生命周期。

#### PermissionService

- 检查辅助功能权限。
- 检查屏幕捕获权限。
- 给出中文说明。
- 打开对应系统设置页面。
- 不主动重复弹系统权限框。

#### WindowLocator

- 在用户触发时读取当前前台应用。
- 验证前台进程的 bundle identifier 为 `com.tencent.xinWeChat`。
- 获取当前聚焦标准窗口的进程、位置和尺寸。
- 通过进程 ID、窗口边界和标题特征匹配 ScreenCaptureKit 的 `SCWindow`。
- 不使用私有 API 获取窗口编号。
- 不枚举或保存其他微信窗口的内容。

#### TargetConfirmationService

- 生成一次性的目标窗口内存预览。
- 展示窗口所属应用、尺寸和缩略图。
- 等待用户确认或取消。
- 确认后立即释放预览图；扫描模块重新按需捕获。

#### ScrollDriver

- 记录开始时的滚动位置。
- 尝试通过辅助功能滚动条设置位置。
- 辅助功能滚动不可用时，使用受限的 `CGEvent` 滚轮事件。
- 只向目标窗口内容区域发送滚动。
- 扫描完成或取消时尽力恢复原位置。
- 不发送文字键盘事件，不执行点击消息、菜单或发送区。

#### WindowCapturer

- 使用 ScreenCaptureKit 捕获目标 `SCWindow`。
- 每次只保留当前帧和上一帧的必要摘要。
- 输出内存中的像素缓冲，不写临时文件。
- 检测窗口尺寸、显示器和缩放变化。

#### VisionOCRService

- 使用 `VNRecognizeTextRequest`。
- 首选 `zh-Hans`，同时允许系统识别数字、拉丁字符和常见符号。
- 采用 `.accurate` 模式。
- 返回文字、候选、置信度和归一化位置。
- OCR 完成后立即释放像素缓冲引用。

#### MessageParser

- 从 OCR 观察中识别昵称行、时间、正文和非文字区域。
- 基于位置和相邻关系形成消息块。
- 不根据语义补全缺失内容。
- 无法确定边界时创建解析警告。

#### TranscriptAssembler

- 按视口顺序拼接消息块。
- 只消除相邻视口的真实重叠。
- 保留真实的重复消息。
- 标记无法可靠拼接的位置。
- 维护是否完整、警告和来源视口索引。

#### MarkdownRenderer

- 生成确定性的 Markdown。
- 保留消息顺序和正文换行。
- 输出提取状态和识别存疑标记。
- 不做摘要、润色、翻译或号码格式化。

#### SettingsStore

- 只通过 `UserDefaults` 保存非敏感设置。
- 保存快捷键、后台常驻、开机自启等配置。
- 不保存扫描结果、窗口标题或文件路径历史。

## 8. 应用状态机

```text
idle
  └─ 用户触发 ─→ checkingPermissions
                       ├─ 缺权限 ─→ permissionRequired ─→ idle
                       └─ 权限通过 ─→ locatingTarget
                                           ├─ 无目标 ─→ targetRejected ─→ idle
                                           └─ 找到目标 ─→ confirmingTarget
                                                               ├─ 取消 ─→ idle
                                                               └─ 确认 ─→ countdown
                                                                              └→ movingToTop
                                                                                     ├─ 失败 ─→ failed
                                                                                     └─ 成功 ─→ capturing
capturing ↔ recognizing ↔ assembling ↔ scrolling
    ├─ 用户操作 ─→ paused
    ├─ 用户取消 ─→ cancelled
    ├─ 窗口变化 ─→ failed
    ├─ 达到限制 ─→ incomplete
    └─ 到达末尾 ─→ restoringPosition ─→ completed

paused
  ├─ 目标仍有效 + 用户继续 ─→ capturing
  ├─ 用户取消 ─→ cancelled
  └─ 目标无效 ─→ incomplete

completed / incomplete / cancelled / failed
  └─ 有部分消息 ─→ resultEditing
  └─ 无消息 ─→ idle
```

状态机约束：

- 同一时间最多存在一个扫描会话。
- 每次状态转换都应携带可展示的中文原因。
- 取消必须是协作式取消，最迟在当前 OCR 请求结束后生效。
- 完成、取消和失败都必须执行图像释放与滚动恢复清理。
- 清理失败不得覆盖原始错误，但应附加次级警告。

## 9. 用户交互设计

### 9.1 待机页

内容：

- 应用名称 ChatUnpack。
- 一句话说明：“把当前打开的合并聊天记录整理成 Markdown”。
- 主按钮“开始汇总”。
- 当前权限状态。
- 全局快捷键提示。
- “设置”入口。

入口行为：

- 全局快捷键是主入口。用户在记录窗口最前面时按下快捷键，程序先绑定当前窗口，再显示确认页。
- 主窗口按钮和菜单栏菜单是备用入口。由于点击它们会使 ChatUnpack 成为前台应用，程序必须先显示“请切回记录窗口”的 3 秒提示并隐藏自身，再在倒计时结束时识别前台微信窗口。
- 备用入口不能读取“最近使用的微信窗口”，也不能在后台预先枚举窗口。

待机页不得展示：

- 最近聊天。
- 历史文件。
- 微信账号状态。
- 后台监控状态。

### 9.2 权限页

分别解释：

- 辅助功能只用于确认目标窗口和滚动。
- 屏幕录制只用于用户确认的当前记录窗口。
- 所有 OCR 都在本机完成。
- ChatUnpack 不读取微信数据库，也不自动发送。

每项权限提供：

- 当前状态。
- “打开系统设置”按钮。
- “重新检查”按钮。
- “取消”按钮。

### 9.3 目标确认页

展示：

- 应用名称“微信”。
- 窗口标题的本地显示。
- 窗口尺寸。
- 一次性缩略图。
- 隐私提示：“缩略图仅保存在内存中，确认后立即释放”。
- “确认并开始”与“取消”。

约束：

- 不在日志记录窗口标题。
- 不自动确认。
- 目标窗口不在一个显示器内时拒绝开始。
- 目标窗口尺寸过小时提示用户放大，不自动改变尺寸。

### 9.4 倒计时

- 默认 3 秒。
- 全局快捷键入口先绑定目标，再倒计时。
- 主窗口和菜单栏入口先提示用户切回记录窗口，在倒计时结束时绑定目标。
- 目标确认后，ChatUnpack 应把焦点还给已经绑定的微信进程，再开始扫描倒计时。
- 提示用户保持记录窗口在最前面且不要操作鼠标键盘。
- 提供取消按钮。
- 倒计时结束前不滚动、不捕获正文。
- 人工操作监控只在目标窗口重新获得焦点且倒计时结束后启用，避免把确认按钮和焦点恢复动作误判为用户干预。

### 9.5 扫描页

展示：

- 当前阶段：回到顶部、正在识别、正在拼接、正在恢复位置。
- 已处理视口数。
- 已识别消息数。
- 低置信度数量。
- 估计完成度；只有能获得可靠滚动条值时才显示百分比。
- “暂停”和“取消”。

不能可靠估计时显示不确定进度，不伪造百分比。

扫描进度使用不抢占键盘焦点的非激活浮层或菜单栏状态展示，不能因为显示进度而把微信目标窗口切到后台。浮层不得覆盖被捕获的目标窗口内容区域。

### 9.6 暂停页

暂停原因示例：

- 检测到鼠标或键盘操作。
- 目标窗口不再位于最前面。
- 目标窗口被移动或缩放。
- 显示器配置发生变化。

只有目标仍然有效时才允许“继续”。窗口已关闭或变为其他窗口时只能结束并查看部分结果。

### 9.7 结果页

内容：

- 完整、未完成或失败状态。
- 消息数量。
- 低置信度数量。
- 可编辑 Markdown 文本。
- “上一个存疑”和“下一个存疑”。
- “复制 Markdown”。
- “保存 Markdown”。
- “清除并关闭”。

低置信度行为：

- 编辑器中高亮整行或对应消息块。
- 用户修改后可将该项标记为已校正。
- 未校正导出时保留 `〔识别存疑〕`。
- 不强制阻止导出，但必须显示剩余存疑数量。

### 9.8 设置页

只包含：

- 全局快捷键，默认 `Control + Option + U`。
- 启用或关闭全局快捷键。
- 关闭主窗口后是否保留菜单栏常驻。
- 开机自启，默认关闭。
- 查看本地诊断日志。
- 清除设置。

设置页不包含账号、云端、历史、模型或 OCR 服务选择。

### 9.9 菜单栏

菜单项：

- 开始汇总。
- 显示主窗口。
- 设置。
- 退出 ChatUnpack。

后台常驻关闭时，关闭最后一个窗口应退出应用。后台常驻开启时，关闭窗口只保留菜单栏进程。

## 10. 目标窗口识别

### 10.1 触发时机

只在用户主动触发后执行目标识别。不能在后台轮询微信窗口。

- 全局快捷键入口在按键发生时立即读取当前前台窗口。
- 主窗口或菜单栏入口在应用隐藏、3 秒切换提示结束后读取当前前台窗口。
- 任一入口都不能使用上一次扫描保存的窗口引用作为新会话目标。

### 10.2 识别顺序

1. 通过 `NSWorkspace.shared.frontmostApplication` 获取最前台进程。
2. 验证 bundle identifier 为 `com.tencent.xinWeChat`。
3. 通过 `AXUIElementCreateApplication` 获取聚焦窗口。
4. 确认角色为标准窗口，并读取位置与尺寸。
5. 调用 `SCShareableContent` 获取可捕获窗口列表。
6. 只在同一进程的窗口中按边界、标题特征和层级匹配目标 `SCWindow`。
7. 无唯一匹配时拒绝开始，不能猜测。
8. 生成一次性预览并由用户确认。
9. 用户确认后重新验证同一进程和窗口边界，再把焦点恢复给该微信进程。
10. 焦点恢复失败时拒绝开始，不能向当前未知前台窗口发送滚动事件。

### 10.3 不依赖固定标题

记录详情可能来自单聊或群聊，窗口标题可能不同。实现不能把标题写死为“群聊的聊天记录”。

标题只作为弱信号。更强的条件是：

- 当前最前台应用是官方微信。
- 当前聚焦窗口是独立标准窗口。
- 用户看到预览后主动确认。

### 10.4 当前可验证事实

2026-08-21 在当前 macOS 环境对官方微信进行了一次严格只读、无点击、无滚动、无复制的结构检查。辅助功能树只暴露标准窗口和标题栏按钮，没有暴露消息正文或可滚动消息节点。

因此 v0.1 不能假设能够通过 Accessibility 直接读取消息文本。Accessibility 只用于窗口确认、状态检测和尽可能稳定的滚动；正文提取必须以 ScreenCaptureKit + Vision OCR 为主。

## 11. 窗口捕获

### 11.1 技术选择

使用 ScreenCaptureKit：

- 通过 `SCContentFilter` 限定用户确认的 `SCWindow`。
- 使用 `SCStream` 获取单帧像素缓冲。
- 每次捕获后立即停止或复用受控的短生命周期流。
- 输出保持在内存中。

不得使用：

- 全屏持续录制。
- 录制所有窗口后再裁剪。
- 把截图写入 `/tmp` 或应用支持目录。
- 私有窗口 API。

### 11.2 捕获区域

捕获目标窗口后，需要计算消息内容区域：

1. 排除系统标题栏。
2. 排除记录页顶部标题和操作区域。
3. 排除窗口边缘阴影。
4. 保留昵称、时间、正文和消息间分隔区域。
5. 不依赖固定像素值，使用窗口比例、OCR 锚点和最小边距共同确定。

初版允许为当前官方微信布局提供内部校准参数，但参数必须使用相对比例，并集中放在一个结构中，不能散落为魔法数字。

### 11.3 稳定帧

每次滚动后不能立即 OCR。应：

1. 等待最短 150 毫秒。
2. 连续捕获两个低分辨率摘要。
3. 当内容区域摘要差异低于阈值时认为页面稳定。
4. 最长等待 2 秒。
5. 超时后暂停并提示“窗口内容尚未稳定”。

稳定检测只保留缩小后的灰度摘要，正文像素缓冲应及时释放。

### 11.4 变化检测

每一帧前检查：

- 前台应用仍为微信。
- 聚焦窗口仍匹配原目标。
- 窗口位置和尺寸未变化。
- 窗口仍完整位于同一显示器。
- 屏幕捕获权限仍有效。

任何一项变化都暂停扫描，不能继续捕获其他窗口。

## 12. 滚动控制

### 12.1 优先级

滚动采用两级策略：

1. 优先使用 Accessibility 暴露的滚动区域或垂直滚动条。
2. 不可用时，使用 `CGEvent` 发送滚轮事件到目标窗口内容区域。

不使用：

- 鼠标点击消息。
- 拖拽选择文字。
- 复制快捷键。
- Home、End、Command+A 等可能影响未知控件的键盘事件。
- 直接调用微信私有方法。

### 12.2 回到顶部

若可读取滚动条：

- 记录初始归一化滚动值。
- 把滚动值设置为最小值。
- 捕获稳定帧确认到达顶部。

若只能发送滚轮事件：

- 记录每次事件的方向和幅度。
- 分批向上滚动。
- 连续三次得到相同内容摘要时判断到达顶部。
- 设置最大向上尝试次数，防止无限循环。

### 12.3 向下扫描

- 每次滚动约 60%～70% 可见消息区域高度，保留足够重叠。
- 重叠区域用于拼接和消息去重。
- 滚动幅度应根据实际视口高度换算，不使用固定设备像素。
- 每次滚动后等待稳定帧。

### 12.4 到达末尾

满足以下任一可靠条件可结束：

- 可访问滚动条值到达最大值，且最后一帧已处理。
- 连续三次向下滚动后，内容摘要和消息序列都没有新增。

只有图像哈希相同但 OCR 尚未完成时不能提前结束。

### 12.5 恢复位置

- 有滚动条值时恢复到记录的初始值。
- 只有滚轮事件时，根据已记录的净滚动量反向恢复，并通过视口摘要做尽力匹配。
- 无法精确恢复时必须提示“原滚动位置未完全恢复”。
- 恢复失败不应丢弃已经提取的结果。

## 13. 人工操作检测

扫描期间监听：

- 鼠标按钮。
- 鼠标显著移动。
- 滚轮输入。
- 键盘按下。
- 应用切换。

监听用途只限于判断“用户正在操作”，不得记录具体按键、输入文字、鼠标轨迹或点击目标。

检测到人工操作后：

1. 立即停止继续滚动。
2. 完成当前不可取消的 OCR 后进入暂停。
3. 重新验证目标窗口。
4. 用户选择继续或结束。

## 14. OCR 设计

### 14.1 Vision 配置

推荐配置：

- `VNRecognizeTextRequest`
- `recognitionLevel = .accurate`
- `recognitionLanguages = ["zh-Hans", "en-US"]`
- `usesLanguageCorrection = false`
- 使用系统当前可用的最新稳定 revision，但测试中固定记录 revision。

关闭语言纠错的原因：ChatUnpack 要忠实转写昵称、号码、缩写和口语。自动语言纠错可能把原文改成更“合理”但错误的文字。

### 14.2 OCR 输入

- 只对消息内容区域执行识别。
- 根据显示缩放保持足够分辨率。
- 不把图像缩小到影响中文小字号识别的程度。
- OCR 前可以进行不改变语义的对比度归一化。
- 明暗主题采用不同的前景/背景预处理参数。

### 14.3 OCR 输出模型

每个观察至少包含：

```swift
struct OCRLine: Sendable, Equatable {
  let text: String
  let confidence: Float
  let boundingBox: CGRect
  let alternatives: [String]
  let viewportIndex: Int
}
```

注意：实际核心模型应避免直接依赖 Vision 类型，使用标准 Swift 类型，方便测试。

### 14.4 置信度

建议初始阈值：

- `confidence >= 0.85`：正常。
- `0.70 <= confidence < 0.85`：预览中提示。
- `confidence < 0.70`：明确标记为存疑。

阈值是内部校准项，不在 v0.1 设置页暴露。

以下情况即使 OCR 置信度较高，也必须标记为结构存疑：

- 时间无法解析。
- 昵称和时间空间关系异常。
- 消息正文跨屏拼接不确定。
- 当前视口没有与上一视口找到可靠重叠。
- 同一区域出现互相冲突的识别候选。

### 14.5 Emoji 和特殊符号

Vision 对 Emoji 的识别不保证完整。处理规则：

- 能识别时保留原字符。
- 明确存在独立表情消息但不能识别时写 `[表情]`。
- 文字中的未知 Emoji 不得用语义相近的 Emoji 替换。
- 无法判断时标记 `〔识别存疑〕`。

## 15. 消息分段

### 15.1 布局假设

当前记录页的可见结构表现为：

- 每条消息顶部左侧是头像和昵称区域。
- 同一行右侧是日期时间。
- 正文位于昵称行下方。
- 相邻消息之间存在垂直间距或分隔线。

这些是当前官方微信布局的观察，不是永久协议。解析器必须允许通过集中配置调整相对位置阈值。

### 15.2 时间锚点

优先通过右侧时间文本识别消息起点。支持的可见形式至少包括：

- `2026年8月21日 09:51`
- `2026-08-21 09:51`
- `09:51`
- 微信当前版本可能展示的“昨天”“星期”等可见前缀

解析器只用于识别结构，Markdown 中应保留 OCR 得到的原始时间文本，不擅自补全年月日。

### 15.3 昵称

- 在时间锚点同一水平带的左侧寻找昵称文字。
- 不使用头像识别身份。
- 不合并视觉相同但文本不同的昵称。
- 昵称识别存疑时标记整条消息。

### 15.4 正文

- 从昵称/时间行下方开始。
- 到下一条消息的昵称/时间行之前结束。
- 按纵向位置排序并保留换行。
- 只去除由布局产生的前后空白，不折叠正文内部空行。
- 不将电话、URL、代码或标点重新格式化。

### 15.5 非文字消息

通过以下信号按优先级判断：

1. 可见类型文字，例如文件名、语音时长或卡片标题。
2. 已知视觉区域形状和 OCR 结果。
3. 消息块中存在明显内容区域但没有正文文字。

只有信号足够可靠时输出具体占位符，否则输出 `[非文字消息]`。

## 16. 跨视口拼接与去重

### 16.1 不能使用全局去重集合

真实聊天可能连续发送完全相同的文字。使用 `Set` 或全局内容哈希去重会错误删除真实消息，因此禁止。

### 16.2 相邻序列匹配

每次只比较：

- 已合并记录末尾的有限消息序列。
- 当前视口开头的有限消息序列。

匹配键由以下部分组成：

- 昵称规范化文本。
- 可见时间文本。
- 正文规范化文本。
- 消息类型。
- 相对垂直顺序。

规范化只允许：

- 统一换行符。
- 去除 OCR 布局产生的行首行尾空白。
- 统一全角/半角空格用于匹配，但输出仍保留原观察文本。

不得为了匹配而修改汉字、号码、标点或大小写。

### 16.3 重叠算法

1. 取上一结果末尾最多 8 条消息。
2. 取当前视口开头最多 8 条消息。
3. 计算最长后缀/前缀序列匹配。
4. 精确匹配优先。
5. 模糊匹配必须同时满足昵称、时间和正文相似度阈值。
6. 只有唯一最佳匹配且分数超过阈值时才删除当前视口中的重叠部分。
7. 匹配不唯一时不猜测，插入拼接存疑标记。

### 16.4 保留真实重复

如果两条相同消息在同一视口中各自具有独立布局位置，必须保留两条。

跨视口只有在它们处于预期重叠位置且序列上下文一致时，才能认定为同一条消息。

### 16.5 消息在接缝处被截断

- 当前视口顶部或底部的半条消息标记为 `partial`。
- 下一视口出现互补部分时进行字段级合并。
- 合并必须以同一昵称、时间或连续正文位置为依据。
- 无法确定时保留两段并标记 `〔拼接存疑〕`，不能静默丢弃。

## 17. Markdown 输出

### 17.1 完整结果

```md
# 聊天记录

- 记录标题：群聊的聊天记录
- 提取时间：2026-08-21 10:30
- 提取状态：完整
- 消息数量：2

---

**昵称** · 2026年8月21日 09:51

消息正文，保留原始换行。

**另一位昵称** · 2026年8月21日 09:52

[图片]
```

### 17.2 未完成结果

```md
> ⚠️ 此记录提取未完成：目标窗口在扫描过程中被关闭。
```

警告必须位于标题元数据之后、正文之前。

### 17.3 存疑内容

```md
**昵称** · 2026年8月21日 09:52

〔识别存疑〕这里有一段无法可靠确认的文字
```

拼接存疑使用：

```md
> 〔拼接存疑〕以下两段内容的跨屏连续关系无法自动确认。
```

### 17.4 输出规则

- 消息严格按扫描后的原始顺序输出。
- 每条消息独立成块。
- 不合并同一用户的连续消息。
- 不添加 AI 总结。
- 不修饰昵称。
- 正文原始换行必须保留。
- 时间保留可见文本，不推断缺失日期。
- 用户在结果页的修改作为最终导出内容。

### 17.5 文件名

默认文件名：

```text
聊天记录-20260821-103000.md
```

- 不把窗口标题或联系人名称自动写入文件名。
- 用户可在保存面板中自行修改。
- 不保存最近导出路径历史。

struct RecognizedField: Sendable, Equatable {

enum MessageKind: String, Sendable, Codable {

### 18.5 数据模型原则

- OCR 原始观察只在扫描阶段存在。
- 结果编辑只操作结构化消息和渲染后的 Markdown。
- 用户校正必须显式覆盖原字段并设置 `isUserCorrected`。
- 不为未来数据库持久化添加 ORM、存储 ID 或迁移字段。

## 19. 并发与资源管理

### 19.1 并发模型

- SwiftUI 和应用状态只在 `MainActor` 更新。
- 扫描会话由单独的协调器串行驱动。
- OCR 在受控后台任务执行。
- 同时最多存在一个 Vision OCR 请求。
- 不并行缓存多个全分辨率窗口帧。

### 19.2 内存目标

- 后台空闲常驻内存目标：不超过约 80 MB。
- 空闲 CPU：接近 0。
- 扫描峰值内存目标：不超过约 350 MB。
- 每一屏 OCR 完成后释放原始截图。
- 只保留上一屏的低分辨率摘要、必要的接缝数据和结构化消息。
- 结果关闭后释放聊天文本。

### 19.3 取消

- 每个循环边界检查 `Task.isCancelled`。
- Vision 请求不能立即取消时，完成当前请求后停止。
- 取消后仍执行滚动恢复和图像清理。
- 取消后的部分结果标记为未完成。

## 20. 设置与持久化

允许持久化：

- 是否后台常驻。
- 是否开机自启。
- 是否启用全局快捷键。
- 快捷键组合。
- 用户是否看过权限说明。

禁止持久化：

- 聊天记录。
- OCR 观察。
- 截图。
- 预览缩略图。
- 窗口标题。
- 微信进程信息历史。
- 导出文件历史。
- 剪贴板内容。

### 20.1 开机自启

- 使用 macOS 13 及以上的 `SMAppService.mainApp`。
- 默认关闭。
- 只有用户在设置页主动开启时注册。
- 注册失败显示错误，不请求管理员权限。
- 应用不在合适位置或签名状态不支持时，给出本地帮助说明。

## 21. 错误设计

错误信息必须包含：

- 简短中文标题。
- 当前发生了什么。
- 用户可以做什么。
- 不包含聊天内容或文件路径隐私。

建议错误代码：

| 错误码 | 场景 | 行为 |
|---|---|---|
| `CU-P001` | 缺少辅助功能权限 | 停止并展示授权说明 |
| `CU-P002` | 缺少屏幕捕获权限 | 停止并展示授权说明 |
| `CU-T001` | 当前前台应用不是微信 | 拒绝开始 |
| `CU-T002` | 无法唯一确定目标窗口 | 拒绝开始 |
| `CU-T003` | 窗口跨越多个显示器 | 提示用户移动窗口 |
| `CU-T004` | 窗口尺寸过小 | 提示用户放大窗口 |
| `CU-C001` | 窗口捕获失败 | 停止并保留已有结果 |
| `CU-C002` | 页面长时间不稳定 | 暂停并允许重试 |
| `CU-S001` | 无法滚到顶部 | 停止，不输出完整状态 |
| `CU-S002` | 无法判断是否到底 | 达到限制后标记未完成 |
| `CU-S003` | 原滚动位置恢复失败 | 保留结果并附加警告 |
| `CU-O001` | Vision OCR 失败 | 重试一次，仍失败则停止 |
| `CU-O002` | 没有识别到消息 | 展示空结果和排障建议 |
| `CU-A001` | 跨屏拼接不可靠 | 保留内容并标记存疑 |
| `CU-U001` | 检测到用户操作 | 暂停 |
| `CU-U002` | 目标窗口被切换或关闭 | 停止并标记未完成 |
| `CU-L001` | 达到视口或时间限制 | 停止并标记未完成 |
| `CU-E001` | 复制失败 | 结果保留在编辑器中 |
| `CU-E002` | 保存失败 | 不清空结果，允许重试 |

## 22. 合成测试窗口

### 22.1 目的

`ChatUnpackFixtureHost` 用于在不触碰真实微信的情况下验证：

- 前台窗口确认。
- 长列表自动滚动。
- 明暗主题。
- OCR。
- 跨屏去重。
- 重复消息保留。
- 用户操作暂停。
- 取消和失败。
- 200 条消息性能。

### 22.2 数据要求

合成数据必须全部虚构，不使用用户截图、真实昵称、真实电话或真实聊天文本。

测试集至少包含：

- 20 条短中文消息。
- 10 条多行长消息。
- 10 条中英文混合消息。
- 10 条包含数字、时间、URL 和标点的消息。
- 连续两条完全相同的真实重复消息。
- 跨屏首尾重复区域。
- 相同昵称的连续消息。
- 不同昵称但正文相同的消息。
- 低对比度文字。
- Emoji 和独立表情占位。
- 图片、语音、视频、文件、链接、小程序和嵌套聊天记录占位。
- 总计 200 条的压力样本。

### 22.3 测试模式安全性

- 只在 Debug 构建或显式测试环境变量下允许识别 FixtureHost。
- Release 构建不能把任意应用窗口当作微信目标。
- 测试模式在界面中显示明显的“模拟数据”标识。
- 测试模式不能改变生产默认权限边界。

## 23. 测试计划

### 23.1 单元测试

#### TimestampParser

- 完整中文日期时间。
- 只有时分。
- 包含“昨天”等可见前缀。
- 不合法时间。
- 正文中的时间不被误识别为消息头。

#### MessageParser

- 正常昵称、时间和正文。
- 多行正文。
- 空正文非文字消息。
- 昵称识别存疑。
- 时间识别存疑。
- 视口顶部和底部半条消息。
- 明暗主题归一化后的相同结果。

#### OverlapMatcher

- 精确重叠。
- OCR 小差异的唯一模糊重叠。
- 无重叠。
- 多个同分候选时拒绝猜测。
- 连续相同消息仍保留真实重复。
- 不同昵称相同正文不去重。

#### TranscriptAssembler

- 三个视口顺序合并。
- 接缝消息字段级合并。
- 取消后的部分结果。
- 拼接存疑警告。
- 超过 200 条提示。

#### MarkdownRenderer

- 完整结果。
- 未完成结果。
- 低置信度标记。
- 非文字占位符。
- 原始换行。
- 确定性输出。
- 不泄漏内部视口索引或 OCR 候选。

### 23.2 集成测试

- 使用 FixtureHost 执行从顶部到末尾的自动扫描。
- 目标窗口切换后必须暂停。
- 移动或缩放窗口后必须暂停。
- 检测用户输入后必须暂停。
- 取消后恢复滚动位置。
- 结束后检查没有截图文件落盘。
- 关闭结果后检查内存对象释放。
- 断网环境中完整运行。

### 23.3 性能测试

- 启动后空闲 5 分钟，记录平均 CPU 和内存。
- 扫描 200 条合成消息，记录峰值内存。
- 长文本和高分辨率窗口分别测试。
- 连续执行 5 次扫描，确认内存不会持续增长。
- 扫描结束后等待 30 秒，确认内存回落。

### 23.4 隐私测试

- 搜索应用支持目录和临时目录，不应出现 PNG、JPEG 或 OCR 原文。
- 搜索日志，不应出现合成昵称和正文。
- 监控网络连接，扫描期间不应建立外部连接。
- 未触发扫描时，不应调用 ScreenCaptureKit 或 Vision。
- 开机自启后保持空闲，不应枚举微信窗口。

### 23.5 真实微信手动验收

本项不由自动化工具执行。只有用户准备好无隐私合并记录并再次明确授权后，才进行：

1. 用户自己打开测试记录。
2. 用户自己触发 ChatUnpack。
3. 用户确认目标预览。
4. ChatUnpack 自动滚动和本地 OCR。
5. 用户检查生成结果。
6. 用户只反馈无隐私的错误描述或模拟内容。

不得要求用户提供真实聊天截图或原始导出文件。

## 28. 已知风险

### 28.1 微信界面变化

微信升级可能改变标题、边距、字体、时间位置和滚动行为。缓解方式：

- 不依赖固定标题。
- 布局阈值集中管理。
- 使用合成测试覆盖解析器。
- 识别不确定时失败并提示，不猜测。

### 28.2 Accessibility 不暴露消息内容

当前只读检查已经确认正文节点未暴露。设计已采用 OCR 主路径，不把 Accessibility 文本读取作为前提。

### 28.3 滚动恢复不精确

当微信不暴露滚动条值时，只能通过滚轮事件和图像匹配尽力恢复。必须在结果页展示恢复警告。

### 28.4 OCR 不是百分之百准确

昵称、号码、Emoji 和低对比度文本可能识别错误。缓解方式：

- 关闭语言自动纠错。
- 高分辨率本地 OCR。
- 低置信度高亮。
- 用户编辑后再导出。
- 未校正结果保留存疑标记。

### 28.5 非文字消息分类

只通过截图不能保证区分所有媒体类型。无法确定时必须使用通用 `[非文字消息]`，不能虚构类型。

### 28.6 账号和协议风险

即使不读取数据库、不注入，第三方 UI 自动化仍可能落入微信服务协议的宽泛限制。产品只按个人自用、用户主动触发、单窗口只读采集设计，不能宣称绝对没有账号风险。

### 28.7 未正式签名

个人自用的 ad-hoc 签名可能导致首次运行提示、TCC 权限在重建后需要重新确认，以及无法直接公开分发。v0.1 接受这一限制。
